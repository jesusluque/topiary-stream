Topiary Stream

Serve MoE models that don't fit — stock kernels, guaranteed floors, measured tolls.

Topiary shapes the tree once; Stream keeps the whole tree alive on disk and lets your RAM hold only the branches the wind is moving.

A 24 GB laptop, serving models it cannot load

The router of a mixture-of-experts model scores its experts before their weights are read — residency decisions are free. Topiary Stream splits every expert into bit planes that stock MLX kernels read directly (P0 = a servable half-byte floor, P0+P1 = bit-exact 4-bit), keeps the hot planes in a gate-governed pool, and guarantees that a cache miss serves the floor — blurry for one frame — never nothing, never a stall.

Pruning removes knowledge, not reasoning

Same model, same day: salience pruning kept MATH/MBPP intact and paid −10 MMLU / −4.4 LAMBADA points — invisible to reasoning-only batteries, which is how it went unnoticed. The paged models buy back exactly that: knowledge lives in total parameter mass, and Stream is how mass that doesn't fit gets served. Speed dividend of pruning, remeasured same-day and interleaved: +6% (108 vs 101–103 tok/s), −2.7 GB.

The coverage law, now same-model

Halving the 80B's resident pool (C 240→120: 47%→23% of its 512 experts/layer, same checkpoint) collapses long-form reasoning — MATH 64%→44%, MBPP 81%→72% — while short-form MMLU holds. Coverage below the routed working set doesn't degrade; it breaks, and it breaks reasoning first. Falsifiable prediction unchanged: at 48–64 GB the same stack serves the 235B.

Cross-family columns are directional (Qwen3 / 3.5 / Next mix technique with model); the original↔pruned and pruned↔Stream pairs are same-model controlled. Full protocol: paper §2.4–2.6.

The breathing runtime

Residency is a dial, so a governor turns it: every refresh reads real memory pressure and resizes the pool. From the measured demo — an external 8 GB allocation against ~3 GB available, generation running:

[gov] avail 4.1 GB → K 32→24 · 13.7 GB active
[gov] avail 3.5 GB → K 24→16 · 13.4 GB active
[gov] avail 3.1 GB → K 16→8  · 13.1 GB active
[gov] avail 3.0 GB → K 8→4   · 12.8 GB active
[balloon] INFLATING 8 GB
[serve] 1106 tokens · 49.3 tok/s · peak 13.85 GB — completed cleanly

Four automatic retreats, no crash, and — because a smaller pool reads fewer planes — the elastic dial trades quality for memory and speed at once.

Honest limits — all measured, not speculated

  • Prefill is served exact by design — the prompt is one batched pass whose P1 union reads once from the memmaps, so the pool policy governs decode only. Before this fix the prefill toll measured +6–11% PPL on the 35B and +28%/+120% on the 80B (flat prefill routing defeats recency); that measurement is why the design changed.
  • The decode-side toll, measured hostile and head-to-head. Token-by-token KLD against the exact base with a live cache (WikiText, exact 16-token prefix): 80B at production C=240 0.774, all-P0 0.582, 30B-Stream with its universal floor 0.131 — coverage first, refresh cadence second (256→32: 0.774→0.303 at up to −47% tok/s, and cadence does not move focal tasks). Duel against Unsloth's UD-Q2_K_XL (Dynamic 3.0) of the same 80B on the same machine (30.1 GB, CPU-only, 12.6 tok/s): MATH-500 65 vs 69, MBPP 81 vs 86, MMLU 85.2 vs 86.2 — at par on knowledge, ~5 points behind on generative tasks (n=100), from 17 GB at 40–70% higher throughput with an exact prompt. Four cheaper fixes were measured and retired (absorb, overflow tier, thin floor, 2-bit gear in tasks: MATH 52%). The residue is the quality of the 2-bit plane itself; we stopped there rather than chase the gap without a clear return.
  • The 235B has no servable middle on 24 GB. Four modes measured: fast-but-collapsed, degenerate floor (its salience is flat), perfect-at-0.2-tok/s, batch-only exact. Falsifiable prediction: at 48–64 GB the same stack serves it.
  • Coverage laws: every routed slot needs a floor — naked drops of dominant slots collapse output; token-level retry needs L·k·P(miss) ≪ 1 (falsified live at 99% retries against load-balanced tails).
  • Speculative decoding is blocked on Qwen's hybrid generation in current mlx-lm (non-trimmable SSM caches) — an implementation limit, with the general solution known in the literature.
  • Salient-prefix subsampling is a memory dial, not a free lunch: an 8-point matrix on the 30B-Stream shows MATH nearly flat from 3.0× down to 1.0× pool bytes (67→64%), but the full battery on the seeming winner (2:2:4) pays −8 MBPP / −3.6 MMLU. Default stays full P1. Two cheaper ideas measured to death: better floor constants (dropped bits are uniform noise, 1.5% MSE) and row-delta compression (neighbor equality = exact chance rate — it expands).
  • Concurrent work is closing the window (adversarial sweep, Aug 19): Tied Trit-Planes folds planes to 4-bit through a bespoke Zig engine; vLLM-Moet gates FP4 recovery on Blackwell. Neither has stock kernels, a hard floor, or published quality accounting — the conjunction this project leads with. Details and citations in the paper's related work.
  • Generality is declared, not claimed: one machine, one family (Qwen3 / 3.5 / Next). Qwen's decode routing is highly local; a load-balanced router could defeat recency-based residency and must be measured before the coverage laws are read beyond "MoE with high decode locality". Stream-serving a Topiary (per-layer-width) checkpoint needs the public per_layer loader from the Topiary repo on PYTHONPATH.
  • Statistics: at n=25/50, ≤2-item gaps are indistinguishable, not ties; n=100 generative tasks carry ±9 points, so the duel's 5-point gaps are directional (consistent across two tasks), not individually significant. Citable throughput after a clean reboot: 35B 47.2 tok/s swap-free (cold round within 1% of warm); the 80B's cold rounds triggered swap and are discarded — its warm 17.3–21.5 stands.

Try it

git clone https://github.com/jesusluque/topiary-stream && cd topiary-stream
uv venv && source .venv/bin/activate && uv pip install -e .
python src/split.py --src mlx-community/Qwen3.5-35B-A3B-4bit \
    --out artifacts/qwen35-stream --layout resident-p0
python src/serve.py --artifact artifacts/qwen35-stream --pool-k 32 --governor

Artifacts

  • qwen3.5-35b-topiary-stream — the flagship (serve on any 24 GB Apple Silicon)
  • qwen3-next-80b-topiary-stream — the strongest model this hardware has touched, served at its true base
  • qwen3-235b-topiary-stream-kit — build kit + the honest negative, for the 48–64 GB machine you'll own someday

The runtime is public (August 2026). The three Stream artifacts above are private pending release; until then, split.py rebuilds any of them from the community 4-bit checkpoint in ~15 min (35B) to ~1 h (80B).
